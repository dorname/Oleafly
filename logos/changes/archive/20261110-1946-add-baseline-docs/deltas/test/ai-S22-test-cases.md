## 一、单元测试用例

### 1.1 API 字段约束（来源：本期无适用来源）

本场景**无 HTTP API 端点与请求体字段约束可提取**：事实来源中的 API delta（`deltas/api/ai-01-mcp-cli-api.md`）确实出现 `list_skills` / `load_skill` / `read_skill_file` 等技能类工具名，但它们属于 **MCP（执行路径⑤外部 MCP client）** 的只读工具集，与 S22 的**内置助手技能调用（执行路径①）**不是同一执行面，按需求 §1.2「五条执行路径不可混称」不得混用；S22 的交互面为桌面内部 typed IPC 与前端技能管理 UI，事实来源未给出 requestBody / parameters 明细。按基线口径**不得发明**字段约束，故本组**无适用 UT 条目**。

### 1.2 DB 约束（来源：本期无适用来源）

本场景**无 UNIQUE / CHECK 约束清单可提取**：事实来源未提供 ai 模块 DB DDL（`deltas/database/` 仅含 core 与 collab 两份）；S22 的技能目录与 catalog 由 Rust 侧 `skills_catalog.rs` 承载，事实来源给出的是**体积上限与 checksum 校验**（catalog 8MiB / archive 64MiB），不是 UNIQUE / CHECK 明细。按基线口径**不得凭空发明**约束，故本组**无适用 UT 条目**；体积与 checksum 相关约束改置于 §1.3 业务规则组。
