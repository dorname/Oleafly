# Oleafly 实时协作 需求文档

> 最后更新：2026-11-09

## 一、产品背景与目标

### 1.1 产品定位（本模块范围内）

collab 模块承载 Oleafly 的实时协作能力：自建 Oleafly Collaboration Server + 桌面/浏览器客户端，覆盖 **服务器接入与项目共享 → 实时共同编辑 → 断线重连 → 离线冲突合并与审查 → 角色权限 → 评论建议与聊天 → 共享历史 → Guest 外部协作者 → 访问日志与控制台 → 通知邮件与配额 → 服务端备份恢复 → 浏览器端（实时协作/会话安全/输出查看）** 全链路。项目内容经 Loro change log 在多端收敛，权限由服务端逐 change 校验。

### 1.2 四条同步路径不可混称

Oleafly 存在四条数据同步路径，能力与语义完全不同，**不得在需求与宣传中混为一谈**：

| 路径 | 归属模块 | 本质 |
|---|---|---|
| ① 实时协作 | **本模块（collab）** | 自建 Oleafly Server + Loro change log + WS 实时收敛，多端共同编辑同一项目 |
| ② 云同步 | sync 模块 | Dropbox/Google Drive/S3 挂载的多设备文件同步，非实时、非共同编辑 |
| ③ 在线 LaTeX 服务桥 | sync 模块 | 与在线 LaTeX 服务的 Git 桥双向同步与项目导入，非实时 |
| ④ 普通 Git hosting | core 模块 | GitHub/GitLab/Gitea/Forgejo/Codeberg 或自建 remote 的 push/pull |

**本模块只覆盖路径①**。其余三条路径的需求见对应模块文档。

### 1.3 核心目标

- 多人经自建 Server 对同一项目实时共同编辑，文本重叠编辑自动收敛，合并结果可审查；
- 断线、离线不丢数据：断线增量补发、离线冲突合并、二进制/路径冲突副本保留、大批量外部变化同步暂停，均有明确行为；
- 权限在服务端逐 change 校验，客户端 UI 不是安全边界；
- 浏览器端可按角色参与协作并保持会话安全，但其能力边界（无离线编辑、无 long-poll 回退、无编译引擎）如实呈现。

### 1.4 目标用户画像

研究团队与小群体：共同撰写论文/学位论文的作者群；需要短期邀请外部协作者（Guest）的项目 Owner；需要审计「谁加入了项目」的负责人；自建 Server 的运维管理员。

## 二、用户痛点分析（本模块相关）

### P01: 多人协作靠传文件
因为协作者之间靠邮件/网盘互传稿件 → 导致互相覆盖修改、版本对不上 → 造成返工与内容丢失。

### P02: 协作数据安全预期错位
因为托管协作文档时用户不清楚服务端存储、会话与备份的可读性边界 → 导致把敏感内容误放托管环境或低估风险 → 造成安全事件与信任受损。

### P03: 协作过程不透明
因为缺少「谁加入/下载/打开了项目」的记录与统一的成员/设备管理入口 → 导致 Owner 无法审计、Admin 无法运维 → 造成责任无法追溯。

### P04: 断网与冲突破坏协作
因为常规协作工具断网即不可用、冲突时静默覆盖 → 导致离线工作成果丢失 → 造成协作信任受损。

## 四、核心场景详述

### S29: 服务器接入与项目共享

- **触发条件**：团队要启用实时协作，接入一台自建 Oleafly Collaboration Server。
- **用户价值**：一键接入 Server 并把项目按角色分享给协作者（← P01）。
- **优先级**：P0
- **主路径**：添加 Server → GitHub/OIDC 登录 → 设备登记 → 分享项目/生成邀请链接并指定角色 → 协作者加入项目开始协作。

#### 验收条件

##### 正常：接入与分享
- **GIVEN** 用户拿到自建 Server 地址
- **WHEN** 添加 Server、经 GitHub/OIDC 登录并完成设备登记后分享项目
- **THEN** 协作者经邀请加入并进入共享项目，按所授角色参与协作

##### 异常：suspended 或已撤销设备
- **GIVEN** 设备被 Server 暂停（suspended）或已被撤销
- **WHEN** 该设备尝试登录/同步
- **THEN** 返回明确错误，不授予访问

##### 异常：协议不兼容
- **GIVEN** 客户端与 Server 的协作协议版本不兼容
- **WHEN** 建立同步
- **THEN** 停止同步并明确报告，不产生半同步状态

##### 边界：首次 admin 初始化
- **GIVEN** 全新 Server 尚无管理员
- **WHEN** 第一个管理员初始化
- **THEN** 必须提供 setup code 才能完成初始化

### S30: 实时共同编辑

- **触发条件**：多个协作者打开同一项目并发编辑。
- **用户价值**：编辑内容、结构与在线状态实时收敛，无需互传文件（← P01）。
- **优先级**：P0
- **主路径**：同项目并发编辑文本与文件树 → 光标与在线状态（presence）实时同步 → 各端内容收敛一致。

#### 验收条件

##### 正常：并发编辑实时收敛
- **GIVEN** 多个协作者打开同一项目
- **WHEN** 并发编辑文本与文件树
- **THEN** 编辑、光标与在线状态经 Server 实时收敛，各端内容一致

##### 异常：过大单批不阻断其他
- **GIVEN** 某单批数据过大被判 Unsendable
- **WHEN** 同步继续
- **THEN** 该批暂不发送，但不阻断其他内容的同步

##### 边界：慢上传与损坏 frame
- **GIVEN** 客户端上传缓慢或个别 frame 损坏
- **WHEN** 同步传输
- **THEN** 慢上传不被 quiet timeout 误判；损坏 frame 不阻断后续 frame 的处理

### S31: 断线重连与增量补发

- **触发条件**：网络中断、Server 暂时不可用或客户端重启。
- **用户价值**：断网期间的工作在恢复后自动补齐，不丢失（← P04）。
- **优先级**：P0
- **主路径**：断网期间继续编辑 → 网络恢复后重连 → 本地未同步变更增量补发并与服务端合并。

#### 验收条件

##### 正常：断线补发
- **GIVEN** 客户端断网期间继续编辑
- **WHEN** 网络恢复重连
- **THEN** 本地变更增量补发并与服务端合并，无丢失

##### 正常：桌面 WS 回退 long-poll
- **GIVEN** 桌面端 WS 连接连续两次失败
- **WHEN** 客户端维持同步
- **THEN** 回退 `/frames`+`/poll` 传输，并每分钟重探 WS 可用性（该回退仅桌面端有，浏览器端无，见 S40）

##### 异常：Server busy 与退避
- **GIVEN** 重连请求收到 429/503 busy
- **WHEN** 客户端重试
- **THEN** 进入长等待而非高频冲击；重连退避含 jitter

##### 边界：重启后幂等
- **GIVEN** 客户端重启后重发已确认的 batch
- **WHEN** 服务端处理
- **THEN** 幂等处理，不重复存储

### S32: 离线冲突合并与审查

- **触发条件**：离线/断线期间产生重叠编辑或外部磁盘变化。
- **用户价值**：文本冲突自动合并、可审查；无法合并的保留副本不丢数据（← P04）。
- **优先级**：P0
- **主路径**：文本经 Loro/OT 自动合并 → 用户在只读 Merge Review 中按作者/diff 审查合并结果 → 二进制/路径冲突保留副本并通知。

#### 验收条件

##### 正常：重叠文本自动合并与 Merge Review
- **GIVEN** 两端离线期间对同一文本产生重叠编辑
- **WHEN** 恢复同步
- **THEN** 文本由 Loro/OT 自动合并，用户可在只读 Merge Review 中按作者与 diff 审查；并非所有重叠文本都要求人工二选一（README "asks before it applies anything" 的概括过宽，实际行为是自动合并+只读审查，见偏差 D12）

##### 异常：二进制/路径冲突
- **GIVEN** 二进制文件或路径冲突无法自动合并
- **WHEN** 同步
- **THEN** 保留双方副本并通知用户，不静默覆盖

##### 异常：大批量外部磁盘变化与写盘失败
- **GIVEN** 项目目录发生大批量外部磁盘变化，或写盘失败
- **WHEN** 同步引擎处理
- **THEN** 大批量外部变化进入同步暂停（用户选 Send/Keep local）；写盘失败退避并通知

### S33: 协作角色权限边界

- **触发条件**：项目内存在 Owner/Editor/Reviewer/Commenter/Viewer 多角色协作。
- **用户价值**：权限边界清晰且在服务端强制，不怕客户端被绕过（← P01）。
- **优先级**：P0
- **主路径**：Owner 邀请成员并授予五角色之一 → 各角色按定义操作（Reviewer 固定 Suggesting 模式）→ Owner 管理成员、链接与停止分享。

#### 验收条件

##### 正常：五角色各司其职
- **GIVEN** 项目含 Owner/Editor/Reviewer/Commenter/Viewer 五角色成员
- **WHEN** 各角色执行各自允许的操作
- **THEN** Reviewer 固定处于 Suggesting 模式；Owner 管理成员、邀请链接与停止分享；各角色操作边界与角色定义一致

##### 异常：越权 change 服务端拒绝
- **GIVEN** 客户端发出超出角色权限的 change
- **WHEN** 到达服务端
- **THEN** 服务端逐 change 校验并拒绝，不依赖客户端 UI 的自我约束

##### 边界：移除/归档与 Viewer pending
- **GIVEN** 用户被移出项目或项目被归档，或 Viewer 在受限期间进行了本地编辑
- **WHEN** 同步发生
- **THEN** 被移除/归档后同步结束；Viewer 期间的本地编辑保留为 pending，权限恢复后可发出

### S34: 评论建议与项目聊天

- **触发条件**：协作者需要审阅、讨论与沟通。
- **用户价值**：评论、建议与聊天都在项目内完成且与权限一致（← P01）。
- **优先级**：P0
- **主路径**：发表评论/回复/mention/resolve → 提出建议并接受/拒绝/撤回 → 项目聊天 → 离线操作排队，恢复后发出。

#### 验收条件

##### 正常：评论建议聊天与离线排队
- **GIVEN** 协作者在项目内评论、提建议、聊天，期间断网
- **WHEN** 恢复连接
- **THEN** 在线操作实时同步；离线期间的评论等操作排队并在恢复后发出

##### 异常：comments off
- **GIVEN** 项目关闭了评论功能
- **WHEN** 有人发表新评论或对既有评论 resolve
- **THEN** 均被拒绝，但文本编辑继续不受影响

##### 异常：角色限制
- **GIVEN** Reviewer 尝试接受建议（包括自己提出的），或 Commenter 尝试改文本/建议/清空他人内容
- **WHEN** 操作提交
- **THEN** 均被拒绝

### S35: 共享历史与版本恢复

- **触发条件**：团队需要回溯或恢复共同编辑的某个版本。
- **用户价值**：完整历史可查可恢复，恢复不破坏历史（← P04）。
- **优先级**：P0
- **主路径**：共享历史由本地完整 Loro change log 构建 → 只读打开/比较版本/命名 → 恢复选定版本（以新 change 形式追加）。

#### 验收条件

##### 正常：查看与恢复
- **GIVEN** 协作者打开共享历史
- **WHEN** 选择某版本查看/比较/命名并恢复
- **THEN** 恢复以新 change 形式追加，旧历史不被抹除

##### 异常：本地无目标版本
- **GIVEN** 本地 change log 不含目标版本
- **WHEN** 尝试打开/恢复该版本
- **THEN** 返回 `history_unavailable`，不凭空构造内容

##### 异常：Reviewer 恢复被拒与非法名称
- **GIVEN** Reviewer 尝试恢复历史版本，或用户输入空名称/超长名称
- **WHEN** 操作提交
- **THEN** Reviewer 可查看历史但不能恢复；空/超长名称被拒绝

### S36: Guest 外部协作者

- **触发条件**：Owner 需要邀请项目外人员临时参与。
- **用户价值**：外部协作者受控、限时、只访问受邀项目（← P01）。
- **优先级**：P1
- **主路径**：Owner 发起邀请 → 审批通过 → Guest 以已验证邮箱登录 → 只访问受邀项目。

#### 验收条件

##### 正常：邀请与受限访问
- **GIVEN** Owner 邀请外部协作者且审批通过
- **WHEN** Guest 以已验证邮箱登录
- **THEN** 只能访问被邀请的项目，不能触及其他内容

##### 边界：默认配置与限流
- **GIVEN** Server 默认配置下启用 Guest
- **WHEN** 发放邀请
- **THEN** Guest 功能默认关闭、审批默认开启；邀请链接 14 天过期、每小时最多 20 个；未配置 SMTP 时提供手工 Add link

##### 异常：越界访问与 admission 终止
- **GIVEN** Guest 登录后尝试查看 directory/分享/邀请，或被移出最后一个项目
- **WHEN** 操作发生
- **THEN** 越界访问被拒绝；移除最后项目后 Guest admission 终止

### S37: 访问日志与管理控制台

- **触发条件**：Owner 需要审计项目访问，Admin 需要运维 Server。
- **用户价值**：加入/下载/打开有记录，成员/设备/域名可管理（← P03）。
- **优先级**：P1
- **主路径**：Owner 开启访问日志 → 查看加入/下载/打开事件 → Admin 经控制台管理成员/设备/域名/安全日志/归档。

#### 验收条件

##### 正常：日志记录与管理操作
- **GIVEN** 项目 Owner 开启访问日志，Admin 使用管理控制台
- **WHEN** 协作者加入/下载/打开项目，Admin 执行管理操作
- **THEN** Owner 可查看对应事件；Admin 可管理成员/设备/域名/安全日志/归档

##### 边界：Admin 不等于内容授权
- **GIVEN** Admin 不是某项目的 Owner
- **WHEN** 尝试读取该项目访问日志或访问项目内容
- **THEN** 项目日志只有项目 Owner 可读；Admin 的项目管理不等于项目内容授权；Server 也可全局禁用访问日志

##### 边界：重连不重复记录
- **GIVEN** 客户端反复重连
- **WHEN** 事件产生
- **THEN** 重连不产生重复日志记录

### S38: 通知邮件与配额限制

- **触发条件**：开放注册的 Server 运营中，需要通知与配额控制。
- **用户价值**：mention/邀请/分享有邮件通知，资源滥用有上限（← P03）。
- **优先级**：P1
- **主路径**：mention/邀请/分享触发邮件异步发送 → 开放注册 Server 配置存储/项目数/上传限制 → 配额内操作正常。

#### 验收条件

##### 正常：邮件发送与配额内使用
- **GIVEN** Server 配置了 SMTP 与开放注册限制
- **WHEN** 用户触发 mention/邀请/分享并在配额内操作
- **THEN** 对应邮件异步发送；存储/项目数/上传限制内的操作正常完成

##### 异常：邮件重试与重启丢失
- **GIVEN** SMTP 暂时不可用，随后 Server 重启
- **WHEN** 邮件队列处理
- **THEN** 按 30s→2m→10m→30m→2h 间隔重试后丢弃；重启会丢失未发送的普通邮件（明确边界）

##### 异常：配额超限
- **GIVEN** 存储配额已满或请求频率超限
- **WHEN** 上传/同步
- **THEN** 存储满返回 413（文本 change 仍可通过），请求超限返回 429

### S39: 服务端备份与恢复

- **触发条件**：灾备演练或事故后恢复 Server 数据。
- **用户价值**：备份-恢复后协作可继续，靠客户端补发收敛（← P02）。
- **优先级**：P1
- **主路径**：fs 模式备份整个 data 目录；S3 模式 DB 与 bucket 一起备份 → 恢复旧库 → 客户端重连补发本地持有的缺失 changes。

#### 验收条件

##### 正常：恢复后客户端补发
- **GIVEN** Server 从 fs 或 S3 模式备份恢复旧库
- **WHEN** 客户端重连
- **THEN** 客户端补发服务端缺失的 changes，项目内容收敛

##### 异常：依赖已丢 change 的更新
- **GIVEN** 某更新依赖的 change 在备份间隙丢失，且原作者当前不在线
- **WHEN** 恢复后同步
- **THEN** 相关更新须等原作者上线后补发，不能凭空收敛

##### 边界：Litestream 不替代对象备份
- **GIVEN** 部署启用 Litestream
- **WHEN** 评估备份完备性
- **THEN** Litestream 只复制 SQLite，不替代 S3 对象备份

### S40: 浏览器实时协作

- **触发条件**：协作者无桌面端，经浏览器访问 Server 参与协作。
- **用户价值**：浏览器按角色完成编辑/建议/评论/聊天/presence（← P01）。
- **优先级**：P0
- **主路径**：浏览器登录 Server → 按角色编辑/建议/评论/聊天/查看在线状态 → 断线恢复时恢复 inflight 与 sessionStorage 中的未确认输入。

#### 验收条件

##### 正常：浏览器按角色协作
- **GIVEN** 用户在浏览器登录 Server
- **WHEN** 按所授角色编辑/建议/评论/聊天/查看 presence
- **THEN** 操作按角色边界执行；断线恢复时 inflight 请求与 sessionStorage 未确认输入被恢复（ack 丢失场景经 transform 处理）

##### 异常：离线新编辑被拒
- **GIVEN** 浏览器处于离线状态
- **WHEN** 发起新编辑
- **THEN** 被拒绝——浏览器没有离线编辑能力；sessionStorage 约 2M 字符/7 天上限，不是跨设备离线队列

##### 边界：无 long-poll 回退
- **GIVEN** 浏览器端 WS 断线
- **WHEN** 重连
- **THEN** 只有 WS 重连，没有桌面端的 `/frames`+`/poll` long-poll 回退

### S41: 浏览器会话安全

- **触发条件**：浏览器客户端访问 Server 的所有会话。
- **用户价值**：会话与写请求有明确防护，风险如实呈现（← P02）。
- **优先级**：P0
- **主路径**：登录建立 30 天会话（HttpOnly/Secure/Lax cookie）→ 写请求校验精确 Origin + `X-Oleafly-Requested-With` → 严格 CSP 禁止 framing。

#### 验收条件

##### 正常：会话建立与写请求防护
- **GIVEN** 浏览器登录成功
- **WHEN** 建立 30 天会话并发起写请求
- **THEN** cookie 为 HttpOnly/Secure/Lax；写请求要求精确 Origin 与 `X-Oleafly-Requested-With` 头；严格 CSP 禁止 framing

##### 异常：会话过期与访问终止
- **GIVEN** 会话过期，或服务端判定 forbidden/not_found/removed/archived
- **WHEN** 浏览器请求
- **THEN** 过期会话视为登出；对应错误结束当前访问

##### 异常：Origin 错误与限流/容量错误
- **GIVEN** 写请求来自错误 Origin，或项目过大/服务繁忙
- **WHEN** 请求到达服务端
- **THEN** Origin 错误按 cross_site 拒绝；返回 `project_too_large`/`server_busy` 明确错误

### S42: 浏览器输出查看

- **触发条件**：浏览器协作者需要查看编译产物并与源文核对。
- **用户价值**：浏览器可读最新 PDF 并做源/PDF 跳转，但不虚构编译能力（← P01）。
- **优先级**：P1
- **主路径**：Owner/Editor 从桌面上传 PDF/SyncTeX → 浏览器读取最新输出 → 源与 PDF 双向跳转。

#### 验收条件

##### 正常：读取上传输出并跳转
- **GIVEN** Owner/Editor 已上传 PDF 与 SyncTeX
- **WHEN** 浏览器协作者打开输出视图
- **THEN** 读取最新上传的 PDF/SyncTeX，支持源/PDF 双向跳转

##### 异常：上传被拒
- **GIVEN** 非 Owner/Editor 尝试上传输出，或文件 magic/大小/main-hash 校验失败
- **WHEN** 上传请求到达
- **THEN** 拒绝该上传

##### 边界：生产浏览器无编译引擎
- **GIVEN** 用户在浏览器中触发编译
- **WHEN** 请求处理
- **THEN** 生产浏览器没有编译引擎，不能编译；fake engine 仅用于开发与测试环境，不等同生产

## 五、约束与边界

### 5.1 技术约束

- **项目内容不是端到端加密**：Server capability 明确 `encryption=None`；宿主、磁盘与备份运营者可读取项目内容。产品描述不得宣传为 E2E 加密。
- **四条同步路径不可混称**（见 1.2）：本模块只是路径①实时协作；与云同步、在线 LaTeX 服务桥、普通 Git hosting 互不替代。
- **README "asks before it applies anything" 概括过宽**（偏差 D12）：实际行为是重叠文本 Loro 自动合并 + 只读 Merge Review，并非一切变更都先询问；文档回补另立变更。
- **浏览器传输回退差异**：桌面端 WS 两次失败可回退 `/frames`+`/poll` 并每分钟重探；**浏览器只有 WS 重连，无 long-poll 回退**，且无离线编辑能力。
- **生产浏览器无编译引擎**：浏览器只查看 Owner/Editor 上传的输出；fake engine 仅限开发与测试（Browser E2E 不等同生产）。
- 权限校验在服务端逐 change 执行，客户端 UI 不是安全边界；协作协议为 collab protocol v1（min/max 协商），协议不兼容停止同步。
