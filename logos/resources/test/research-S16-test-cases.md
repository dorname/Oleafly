## 一、单元测试用例

### 1.1 API 字段约束（来源：本期无适用来源）

本场景**无 HTTP API 端点与请求体字段约束可提取**：事实来源中的 API delta（`deltas/api/ai-01-mcp-cli-api.md`）只覆盖 MCP localhost 端点与 CLI JSON 契约（AI 执行路径④⑤），与 S16 的引用检索面板无交集；S16 的交互面是桌面内部 typed IPC 与前端面板，事实来源未给出 requestBody / parameters 明细。按基线口径**不得发明**字段约束，故本组**无适用 UT 条目**。

### 1.2 DB 约束（来源：本期无适用来源）

本场景**无 UNIQUE / CHECK 约束清单可提取**：事实来源未提供 research 模块 DB DDL（`deltas/database/` 仅含 core 与 collab 两份），inventory「数据资产」段只列出本地五库名称与 schema 版本，没有 UNIQUE / CHECK 明细。S16 的权威落点是**项目本地 `.bib` 文件**（文件系统，非 DB 表），按基线口径**不得凭空发明**约束，故本组**无适用 UT 条目**。

## 二、场景测试用例

### 2.1 主路径：文献检索与引用写入

| ID | 描述 | 覆盖 Steps | 前置条件 | 操作序列 | 预期结果 |
|----|------|-----------|---------|---------|---------|
| ST-S16-01 | 按 DOI 单条检索并插入引用、追加 `.bib`、完成 key 诊断 | Step 1→8 | 项目已存在且含 `.bib`；检索 provider 可用 | 1) 在引用检索入口输入 DOI 发起检索；2) 从候选列表选定条目；3) 确认插入引用；4) 执行 `.bib` 追加；5) 执行引用 key 补全 / 校验 / 诊断 | 文稿出现引用标记；`.bib` 追加对应条目；界面同时呈现插入结果、`.bib` 追加结果与 key 诊断结论 |
| ST-S16-02 | DOI / arXiv / URL / 标题多来源检索结果合并查重后展示 | Step 1→5 | 至少两个 provider 可用，且返回结果中含跨源重复条目 | 1) 分别以 DOI、arXiv、URL、标题检索；2) 汇总各来源结果；3) 执行合并查重去重；4) 展示候选列表 | 候选列表中重复条目只出现一次；每条候选保留来源标识，供用户选定 |
| ST-S16-03 | key 缺失与 key 非法的补全、校验与诊断 | Step 7→8 | 检索结果中同时含缺 key 条目与非法 key 条目各一 | 1) 选定缺 key 条目并插入；2) 选定非法 key 条目并插入 | 缺 key 条目给出补全候选；非法 key 条目给出校验结果与诊断信息；非法 key 未写入 `.bib` |
| ST-S16-04 | 追加语义：插入引用不破坏 `.bib` 既有条目 | Step 6→7 | `.bib` 已含多条既有条目 | 1) 插入一条新条目；2) 通读 `.bib` 全文 | 既有条目完整保留，新条目以追加方式写入，无重复写入、无既有条目被覆盖 |
