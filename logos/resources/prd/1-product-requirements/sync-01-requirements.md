# Oleafly 云同步与在线服务 需求文档

> 最后更新：2026-11-09

## 一、产品背景与目标

### 1.1 产品定位（本模块范围内）

Oleafly 是本地优先（local-first）的研究写作工作区。sync 模块承载「云同步与在线服务」三件事：① 经用户自有云存储（Dropbox / Google Drive / S3）在多台设备间同步项目库（Library）项目与设置；② 在线 LaTeX 服务桥（实现内部称 overleaf）——既有项目批量导入与 Git 桥双向同步；③ 外部连接器凭据安全（Git hosting / Zotero / alphaXiv）。

**关键口径：云同步 ≠ 实时协作，两者是正交的两套机制，不可混称。**

- **云同步（本模块）**：设备间、文件级的最终一致同步，基于云存储上的 manifest 比对。双侧修改普通文件时**不做文本合并**，而是保留冲突副本（两个版本都留，如 `main (Laptop 日期).tex`），由用户比对收敛；`project.json` 与设置类走 merge3 三方合并。解决的是「同一人在多台设备间继续工作」。
- **实时协作（collab 模块，S29-S42）**：基于 Loro CRDT change log，多端并发编辑实时收敛，文本自动合并并提供只读 Merge Review。解决的是「多人同时编辑同一项目」。
- 两套机制独立运行、互不替代：不得把云同步宣传为实时协作，也不得把 CRDT 自动合并能力宣传到云同步路径上。

### 1.2 核心目标

- 用户用自己的云存储（Dropbox / Drive / S3）在多台设备间获得一致的 Library 项目与设置，无需人工拷贝；
- 任何一侧的修改都不被静默覆盖：冲突保留双方版本，批量删除有 hold 保护与 Trash 兜底；
- 与在线服务的往来（导入、Git 桥双向同步）逐项可见、失败可定位；外部凭据 token 不落入命令行参数、URL 或 `.git/config`。

### 1.3 目标用户画像

在台式机、笔记本与实验室机器之间切换工作的研究者；需要把在线 LaTeX 服务上的既有项目迁入本地或保持双向同步的用户；接入 Git hosting / Zotero / alphaXiv 等外部账号服务、重视凭据不泄露的用户。

## 二、用户痛点分析（本模块相关）

### P01: 多设备工作上下文割裂
因为台式机、笔记本与实验室机器各自保存项目副本 → 导致靠人工拷贝对齐版本 → 造成最新稿被旧稿覆盖或丢失。

### P02: 跨设备误删放大
因为一处误删会随同步扩散到所有设备 → 导致整批文件消失且难以察觉 → 造成稿件损失。

### P03: 在线平台锁定
因为既有工作沉淀在在线 LaTeX 服务上 → 导致迁出或双向保持一致只能手工搬运 → 造成工作流割裂与反复搬运成本。

### P04: 外部凭据散落
因为 Git hosting、Zotero、文献检索需要长期 token → 导致凭据散落在命令行参数、URL 或仓库配置中 → 造成泄露风险且难以追踪。

## 四、核心场景详述

### S43: 云同步多设备协作

- **触发条件**：用户在多台设备间继续同一项目工作。
- **用户价值**：用自己的云存储获得多设备一致的 Library，无需人工拷贝（← P01）。
- **优先级**：P0
- **主路径**：连接 Dropbox / Google Drive / S3 账户 → 同步 Library 项目与设置 → 在另一设备连接同一账户 → 继续同一项目。

#### 验收条件

##### 正常：多设备同步
- **GIVEN** 两台设备连接同一云存储账户
- **WHEN** 设备 A 修改 Library 项目与设置并完成同步，设备 B 触发同步
- **THEN** 设备 B 获得对应的项目内容与设置更新，可继续编辑

##### 正常：S3 密钥保存前检查
- **GIVEN** 用户配置 S3 作为云存储
- **WHEN** 保存凭据
- **THEN** 先执行 probe 与条件写检查，通过后才保存密钥

##### 异常：同步范围与上限
- **GIVEN** Library 之外的任意 linked folder、项目内 `.git` 历史与 checkpoints，或单项目规模超过上限
- **WHEN** 云同步运行
- **THEN** 只同步 Library 中有 `project.json` 的项目（不含任意 linked folder）；`.git` 历史与 checkpoints 不随云同步；单项目受 100000 文件与 manifest 64MiB 上限约束

### S44: 冲突副本与三方合并

- **触发条件**：两台设备先后修改了同一文件后同步。
- **用户价值**：双侧修改都不丢，冲突可见、可收敛（← P01）。
- **优先级**：P0
- **主路径**：普通文件双侧修改 → 保留两个版本（冲突副本以 `main (Laptop 日期).tex` 类命名）→ 后到者保留双方 → 用户比对后收敛；`project.json` 与设置类走 merge3 三方合并。

#### 验收条件

##### 正常：普通文件冲突副本
- **GIVEN** 设备 A 与设备 B 均修改了同一普通文件，先后完成同步
- **WHEN** 后到的一侧同步
- **THEN** 不覆盖先到的版本：两个版本都保留（冲突副本含设备与日期命名），后到者保留双方，可比对后收敛

##### 正常：元数据三方合并
- **GIVEN** `project.json` 或设置在双侧被修改
- **WHEN** 同步
- **THEN** 走 merge3 三方合并而非冲突副本；同字段 metadata 冲突时 local 获胜

##### 异常：未保存缓冲保护
- **GIVEN** 编辑器存在未保存（dirty）缓冲
- **WHEN** Download / LocalDelete / MetaMerge 类同步操作到来
- **THEN** 改为 Carry 处理，不覆盖未保存缓冲

##### 异常：冲突副本上传前保护
- **GIVEN** 冲突副本尚未上传成功
- **WHEN** 用户继续当前编辑
- **THEN** 当前编辑不被冲突副本处理覆盖

### S45: 批量删除保护与回收站

- **触发条件**：一次删除大量文件，或另一设备的删除经同步传播到本机。
- **用户价值**：误删有兜底，删除可恢复（← P02）。
- **优先级**：P0
- **主路径**：大批量删除触发 hold → 用户选择 restore 或确认 delete；远端传播的删除进入 Trash（保留 30 天）。

#### 验收条件

##### 正常：远端删除进回收站
- **GIVEN** 文件在设备 A 被删除且删除经同步传播
- **WHEN** 设备 B 同步该删除
- **THEN** 被删文件进入 Trash 而非直接消失，30 天内可恢复

##### 异常：本地批量删除 hold
- **GIVEN** 本地一次删除超过 20 个且过半项目文件，或删除全部文件
- **WHEN** 同步引擎处理该删除
- **THEN** 进入 hold 状态，等待用户 restore 或确认 delete；本地与远端分别判定

##### 异常：tombstone 异地暂停
- **GIVEN** 远端 tombstone 传播的删除在本机判定为异常大规模删除
- **WHEN** 处理该删除
- **THEN** 暂停执行，不删除本地文件

### S46: 云账户切换与断开

- **触发条件**：更换云存储账户，或解除设备与云同步的绑定。
- **用户价值**：切换与断开结果可预期，不留半连接状态（← P01）。
- **优先级**：P1
- **主路径**：切换账户时先停止旧账户 sweep 再接入新账户；Disconnect 时尝试 revoke 远端授权并清除本地密钥。

#### 验收条件

##### 正常：账户切换
- **GIVEN** 设备已连接云账户 A
- **WHEN** 用户切换到账户 B
- **THEN** 先停止旧账户的 sweep，再以新账户继续同步

##### 正常：断开并撤销授权
- **GIVEN** 用户在已连接状态执行 Disconnect
- **WHEN** 断开完成
- **THEN** 尝试 revoke 远端授权并清除本地保存的密钥

##### 异常：revoke 失败仍完成本地断开
- **GIVEN** revoke 请求失败（如无网络）
- **WHEN** 执行 Disconnect
- **THEN** 本地断开仍完成，并如实返回 `remoteRevoked:false`（远端授权未撤销）

##### 边界：账户状态一致性
- **GIVEN** 云同步状态写入与 token 刷新
- **WHEN** 状态写入或 token 刷新发生
- **THEN** 写入校验 account id 防止账户污染；token 刷新绑定 expected account，不跨账户误用

### S47: 在线 LaTeX 服务项目导入

- **触发条件**：用户在在线 LaTeX 服务上有既有项目，需要迁入本地。
- **用户价值**：批量、逐项可追踪地把在线项目迁入本地 Library（← P03）。
- **优先级**：P1
- **主路径**：登录在线 LaTeX 服务 → 列出项目 → 批量导入（并行执行，逐项独立报告成功/失败）→ 保存来源设置。

#### 验收条件

##### 正常：批量导入
- **GIVEN** 用户已登录在线 LaTeX 服务并看到项目列表
- **WHEN** 选择多个项目批量导入
- **THEN** 并行导入且逐项独立报告成功/失败，单项失败不阻断其他项；来源设置被保存

##### 异常：登录会话过期
- **GIVEN** 登录窗口 20 分钟已过或 session 过期
- **WHEN** 用户执行导入操作
- **THEN** 清理会话回到登录态，要求重新登录后再继续

##### 边界：导入取消能力
- **GIVEN** 批量导入进行中，用户希望取消
- **WHEN** 查阅或尝试取消能力
- **THEN** 本基线不声称支持取消：ZIP 导入的取消能力未在实现与测试中确认，文档与宣传不得写成支持

### S48: 在线服务 Git 桥双向同步

- **触发条件**：本地项目与在线服务上的对应项目需要保持一致。
- **用户价值**：不经手工搬运，本地与在线双向同步（← P03）。
- **优先级**：P0
- **主路径**：link 本地项目到在线服务项目 → 手动触发或条件满足时 auto 双向同步。auto 条件：页面可见、无 dirty、无冲突、有 token、静默 15 秒；首次 2 秒后触发，其后每 3 分钟。

#### 验收条件

##### 正常：手动双向同步
- **GIVEN** 项目已 link 到在线服务
- **WHEN** 用户手动触发同步
- **THEN** 本地与远端双向同步完成，内容一致

##### 正常：auto 同步按条件触发
- **GIVEN** 页面可见、无 dirty 编辑、无冲突、token 可用且已静默 15 秒
- **WHEN** auto 同步判定
- **THEN** 首次在 2 秒后触发，其后每 3 分钟一次

##### 异常：条件不满足不推送
- **GIVEN** dirty 编辑、未解决冲突、无 token 或页面不可见任一条件不满足
- **WHEN** auto 周期到达
- **THEN** 不执行推送——auto 不是无条件定时推送

##### 异常：远端持续变化与并发
- **GIVEN** 远端在同步期间持续变化（三轮未收敛），或前一同步尚未结束又触发新同步
- **WHEN** 同步执行
- **THEN** 持续变化以 `SyncKeptChanging` 收尾；并发触发返回 `SyncBusy`，不叠加执行

##### 异常：同文件冲突与首链选择
- **GIVEN** 同一文件在双侧被修改，或首次同步链路需要用户选择来源（NeedsChoice）
- **WHEN** 同步处理
- **THEN** 同文件冲突 abort 回到 base 并逐文件选边；首链选 remote 前先保存本地 backup ref，本地内容可回退

##### 边界：unlink 备份与错误分类
- **GIVEN** 用户 unlink 项目，或同步出错
- **WHEN** 解除链接或错误返回
- **THEN** unlink 导出本地备份；错误按 `AlreadyLinked`、`after_files_changed` 等分类明确返回，不混为一般失败

### S49: 外部连接器凭据安全

- **触发条件**：接入 Git hosting、Zotero、alphaXiv 等需要账号凭据的外部服务。
- **用户价值**：凭据最小暴露，离线可降级工作（← P04）。
- **优先级**：P1
- **主路径**：接入 Git hosting / Zotero / alphaXiv 账号 → 用于 publish / push / pull、引用与文献检索 → 断开或离线时明确降级。

#### 验收条件

##### 正常：凭据受控传递
- **GIVEN** 已接入外部账号
- **WHEN** 执行 publish / push / pull、引用或文献检索
- **THEN** token 只经匹配 base URL 的 credential helper 与环境变量传递，不进 argv / URL / `.git/config`

##### 正常：离线降级
- **GIVEN** 网络不可用
- **WHEN** 使用相关功能
- **THEN** 明确降级：本地缓存与本地 Zotero 仍可用，不伪装在线成功

##### 异常：remote URL 含密码
- **GIVEN** remote URL 内嵌了密码
- **WHEN** 执行 Git 操作
- **THEN** 拒绝该 remote，不使用含明文密码的 URL

##### 边界：凭据存储与错误脱敏
- **GIVEN** 长期凭据落盘与对外错误呈现
- **WHEN** 存储凭据或返回错误
- **THEN** 长期凭据以 AES-256-GCM 加密、0600/owner ACL 保存；错误按类别返回且经脱敏，不回显 token

## 五、约束与边界

### 5.1 技术约束

- **同步范围**：只同步 Library 中有 `project.json` 的项目，不含任意 linked folder（`cloud/provider.rs`、`engine.rs`）。
- **不同步内容**：`.git` 历史与 checkpoints 不随云同步；检查点与本地 Git（core 模块 S12/S13）与云同步完全独立、互不替代。
- **规模上限**：单项目 100000 文件、manifest 64MiB 上限。
- **冲突语义**：普通文件双侧修改保留冲突副本（两版本都留），不自动合并正文；`project.json`/设置走 merge3；同字段 metadata 冲突 local 获胜。
- **删除保护**：批量删除 hold（>20 且过半、或删全部；本地/远端分别判定）；远端删除进 Trash 保留 30 天。
- **凭据安全**：外部凭据 token 不进 argv / URL / `.git/config`，只经匹配 base URL 的 credential helper 与环境变量传递；长期凭据 AES-256-GCM 加密、0600/owner ACL；remote URL 含密码一律拒绝。
- **在线服务桥**：登录窗口 20 分钟；auto 同步非无条件定时推送（页面可见 + 无 dirty + 无冲突 + 有 token + 静默 15s）；**在线服务 ZIP 导入的取消能力未确认，本基线不得声称支持**。

### 5.2 现状声明（未验证项）

- 本基线为静态盘点：上文行为均有实现与测试证据（`cloud/`、`overleaf/`、`oleafly-online/`、`forge/remote_auth.rs`、`oleafly-secrets/` 及对应测试），但**未在本次执行任何测试**；真实云服务商账户（Dropbox/Drive/S3）下的动态行为、auto 同步计时精度、批量导入并发表现均在 verify 阶段单独取证。
- 在线服务 ZIP 导入「可取消」未在实现与测试中确认，不得在任何文档或宣传中写成支持取消。

### 5.3 "不做"清单（本基线范围）

- 不新增任何功能或交互；只固化现状。
- 本模块不描述实时协作、Loro CRDT 合并、服务器共享与角色权限（属 collab 模块 S29-S42）；云同步与实时协作两套机制不得混称，云同步的冲突副本/merge3 不得被宣传为 CRDT 自动合并。
- 在线服务导入不声称支持取消（能力未确认）。
- 不修复文档偏差本身（文档回补另立变更），基线一律以实现为准。
- 不在本模块内描述 AI、研究工具能力（分属 ai/research 模块）。
